# Steam Cloud Manager

[English](README.md) · [Безопасность](SECURITY.md)

Локальный менеджер сохранений Steam Cloud: просмотр файлов, резервные ZIP-копии и удаление выбранных сохранений. Лицензия MIT. Интерфейс на русском и английском, системная/светлая/тёмная тема, избранное, поиск и подгрузка карточек при прокрутке.

## Архитектура

Приложение запускается **на вашем компьютере**. Локальный процесс Node.js обращается к Steam и хранит токены сессии в памяти. На Vercel размещается только публичный сайт с описанием и инструкцией: без API входа в Steam, сессий, файлов или прокси.

Это не решение «только браузер»: требуется локальный процесс. При проверке Steam отклонил WebSocket с origin сайта проекта, но принял соединение без Origin и с origin Steam Community. Полную сессию Steam мы не перенаправляем через хостинг. Точные границы защиты и оставшиеся риски описаны в SECURITY.md. Независимый аудит безопасности не проводился.

## Запуск

Нужен Node.js 22.12 или новее.

```sh
git clone https://github.com/famence/steam-cloud-manager.git
cd steam-cloud-manager
npm ci
npm run build
npm start
```

Откройте `http://127.0.0.1:3000` и подтвердите QR-код в Steam Guard. Для разработки используйте `npm run dev` и адрес `http://127.0.0.1:5173`. Настройки необязательны; пример — `.env.example`. Старый внешний `APP_ORIGIN` нужно удалить: публичное размещение Steam-бэкенда теперь запрещено.

## Библиотека

DLC, инструменты и саундтреки исключаются по типу приложения из Steam, а не по названию. Избранное сохраняется только в текущем браузере, отдельно для каждого SteamID. Избранные игры с сохранениями или неизвестным статусом идут первыми. Подтверждённо пустые игры и игры без Cloud остаются в конце, серыми — в том числе если они избранные.

Метаданные библиотеки загружаются одним запросом; карточки и обложки показываются порциями по 24 при прокрутке. Проверка сохранений выполняется небольшими порциями, не более двух запросов одновременно на аккаунт. Ошибка проверки и отсутствующие метаданные никогда не означают «0 файлов».

## Скачивание и удаление

Сначала скачайте и откройте резервную копию. В браузерах с File System Access API файл записывается потоком на диск. В остальных браузерах появляется ссылка на скачивание. Для удаления нужно закрыть игру/GFN, проверить перечень файлов и ввести фразу подтверждения. План одноразовый, ограничен по времени; актуальность файлов проверяется сервером. Отката и корзины нет. Переименование и загрузка файлов пока не реализованы.

## CI и Vercel

`npm run check` проверяет типы, тесты и обе сборки. Для браузерных тестов: `npm run test:browser:install`, затем `npm run test:e2e`. GitHub Actions запускает проверки на Node.js 22/24 и Chromium без настоящего Steam-аккаунта. Права CI — только чтение; секреты Steam не нужны.

Импортируйте репозиторий в отдельный проект Vercel. Конфигурация публикует только `dist/public`. Для canonical и sitemap задайте `SITE_URL` — окончательный HTTPS-origin — либо используйте системную переменную `VERCEL_PROJECT_PRODUCTION_URL`. Без известного домена и на preview включён noindex. Публичные страницы `/en/` и `/ru/` заранее отрисованы в HTML; личный локальный интерфейс не индексируется.

Перед открытием репозитория проверьте Git-историю, включите приватные сообщения об уязвимостях, защиту ветки и обязательные проверки. Наличие workflow само по себе не включает эти настройки аккаунта. Подробности — в README.md и SECURITY.md.
